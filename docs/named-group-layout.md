# Center a named address group

In the browser, open **Plot Layouts** and enter an attribution name in **Center named group**. The browser suggests matching active names from the investigation as you type. Name matching ignores capitalization. Choose **Save layout settings**, or generate a layout to save the preferences and plot together. These preferences belong to the investigation and survive restarts. **Workspace defaults** provides the same field as a starting value for new investigations; changing it does not affect existing cases. The terminal retains this field in its investigation settings and also offers workspace defaults for new investigations.

Generate a layout to inspect the arrangement, then choose **Sync with Miro** and **Sync and reorganize** to apply it to an existing board. Leave the field blank to generate the normal layout. Previously saved Plot Layouts keep their captured appearance when this preference changes. To use a new preference, generate and sync a new layout. Older ELK previews and plots without captured settings may need regeneration; changed evidence or attribution inputs still require a fresh layout.

This option favors a central arrangement of the selected group's individual addresses and transactions between them, with other activity branching around that structure. Transaction direction, address identities, connections, tracing limits, and fetched evidence remain unchanged. It does not start a trace or fetch additional transactions. Mermaid uses its own arrangement.

Addresses explicitly listed in **Separate branch hubs** restart their layout tree depth and retain a separate entry lane, and explicit change-output rows take priority where alignment conflicts. If the current graph contains no matching addresses, it keeps its normal layout. The preview reports how many address objects and connecting transactions matched. Dense graphs, shared addresses, and disconnected activity can prevent a perfectly straight central tree; the layout still preserves every existing connection.

Outside the selected group, local branch ordering keeps each transaction’s exclusive outputs together and brings connected inputs, transactions and outputs closer. That order continues through later forks and takes priority over vertical date order. Compacting an arranged graph preserves the order within each dependency column so unrelated outputs cannot move between siblings. Shared addresses remain single objects; actual joins may still require crossings.
